Overview

There is no fixed gun. You start from a chassis and build the weapon part by part.

Every part can change the weapon’s stats, how it fires, how it handles ammunition, and what its shots do when they land. That allows some very strange combinations, so the system underneath has to stay readable.

I’m building it as a polished systems prototype and vertical slice. The focus is a modular architecture, clear feedback for the player, and fast testing so I can keep balancing.

Eight ways a shell can fly

Launcher shells take parts like a propulsion, a shell type and a detonator, and together they decide how the shot moves and when it goes off. Pick one.

  • Lobbed, scuttle, corkscrew, and bouncing shots change how a shell travels.
  • Sticky, timed, proximity, and manual detonation change when it goes off.

What I’m building

Weapon chassis

Rifle, launcher, pulse, and beam chassis, each with its own firing model, ammunition rules, and part slots.

Modular parts

Stocks, barrels, triggers, magazines, payloads, propulsion, shells, detonators, dispersal, and dynamics all reshape the finished weapon.

Stats and balancing

Damage, recoil, accuracy, stability, range, fire rate, reload time, and clip size run through one calculation pipeline, built on data tables so new parts slot in without new code.

The builder UI

Inspect parts, compare a temporary build against the current one, manage inventory, duplicate builds, and preview every change before you commit.

Projectile behaviours

Shells that lob, scuttle, corkscrew, bounce, stick, or wait for a timer, a target, or your trigger.

Testing loop

Build a weapon, take it into a test range, judge how it performs, then go back and change parts.

Where it’s at

I’m finishing the chassis, part behaviours, stat pipeline, preview screens, and inventory. Most of the work right now is in the unusual projectile behaviours and the edge cases you get when several parts change the same weapon.

Balancing comes from playtests, debugging, surveys, and adjusting formulas. The goal is that strange builds stay fun without automatically beating a sensible one.
