02 // Overview

The idea

Rather than bolting attachments onto a fixed gun, you start with a weapon chassis and build its identity through interchangeable parts.

Recoil Works is inspired by the weapon building in Loadout. Each part can change stats, firing behaviour, ammunition handling, payload effects, projectile movement, and the situations the finished weapon is best at. That allows some very unusual combinations, so the system underneath has to stay readable.

I built it as a polished systems prototype and vertical slice for my MSc master project. The focus was a modular architecture, clear player feedback, fast testing, and steady balancing.

How it came together

I built the weapon chassis, part behaviours, the stat calculation pipeline, the weapon preview screens, inventory interactions, and the testing workflow.

A lot of the work went into unusual projectile behaviours and the edge cases you get when several parts change the same weapon. Balancing came from playtests, debugging, surveys, and adjusting formulas, so strange builds stay fun without automatically beating a sensible one.

03 // Systems

What I built

01

Weapon chassis

Rifle, launcher, pulse, and beam chassis, each with its own firing model, ammunition rules, and part slots.

02

Modular parts

Stocks, barrels, triggers, magazines, payloads, propulsion, shells, detonators, dispersal, and dynamics all reshape the finished weapon.

03

Projectile behaviours

Launcher shells can be lobbed, scuttle, corkscrew, bounce, stick, or wait for a timer, a target, or a manual detonation.

04

Stats and balancing

Damage, recoil, accuracy, stability, range, fire rate, reload time, and clip size run through one calculation pipeline built on data tables, so new parts slot in without new code.

05

Builder UI

Inspect parts, compare a temporary build against the current one, manage inventory, duplicate builds, and preview every change.

06

Testing loop

Build a weapon, take it into a test range, judge how it performs, then go back and change parts.
